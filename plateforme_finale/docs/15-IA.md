# 15 — Assistant IA (lot 9)

> Ajouté le 2026-10-15 : le prof a demandé que l'application finale « contienne une IA ». Lié à : [[08-Decisions-ouvertes]] #12 et #38, [[11-Protection-des-donnees]], [[13-Demo-presentation]].

## 1. Ce que fait l'IA
| Fonction | Où | Rôle |
|---|---|---|
| **Assistant** (questions-réponses) | menu **Aide → Assistant** (`/assistant/`), tous les rôles | répond aux questions sur l'utilisation du site, **à partir de l'aide du rôle de la personne** (un étudiant n'a que l'aide étudiant) |
| **Relecture du sujet de stage** | bouton sous le champ « sujet » de la fiche (étudiants) | 3 à 5 remarques : précision, activités, outils, livrable, niveau ingénieur |

**Principe : l'IA propose, l'humain décide.** Elle ne valide, ne refuse et n'enregistre rien. La relecture ne bloque pas la soumission : c'est l'encadrant qui valide la fiche. Chaque réponse porte la mention « Généré par une IA, peut contenir des erreurs ».

## 2. Comment ça marche
```
question ─► effacement des e-mails / téléphones / longs nombres, limite de 600 caractères
        ─► plafond de 30 demandes par personne et par heure
        ─► consigne = aide du rôle + règles du processus ─► Google Gemini (appel côté serveur)
        ─► réponse nettoyée (texte brut) ─► affichée avec la mention IA
        ─► en cas d'échec (pas de clé, pas d'Internet, quota, erreur) : MODE DE SECOURS
```
- **Mode de secours (« mode démonstration »)** : sans IA, on cherche dans la page d'aide la question fréquente ou l'étape qui ressemble le plus à la question ; la relecture applique des règles simples (sujet trop court, pas d'activité, pas d'outil, pas de livrable). L'écran dit clairement qu'on est sans IA. **La démo ne tombe donc jamais en panne.**
- Code : `app/espaces/assistant.py` (aucune bibliothèque en plus : appel HTTPS avec `urllib`), vues dans `espaces/views.py`, page `templates/espaces/assistant.html`, script `static/js/assistant.js`. 21 tests (`espaces/tests_assistant.py`), **aucun n'appelle le vrai service** (un filet de sécurité fait échouer tout appel réseau).

## 3. Configuration
- **Fournisseur** : Google Gemini (niveau gratuit). Modèle par défaut : `gemini-flash-lite-latest` (alias qui suit le modèle Lite actuel : Google retire régulièrement les anciens modèles, par exemple `gemini-2.5-*` n'est plus proposé aux nouveaux comptes). Modifiable avec la variable `IA_MODELE`.
- **Clé d'API** : jamais dans le code ni dans Git. Deux façons, la première trouvée est utilisée :
  1. variable d'environnement `GEMINI_API_KEY` ;
  2. fichier `app/cle_gemini.txt` (une ligne : la clé), **ignoré par Git** (`.gitignore`).
- Obtenir une clé : <https://aistudio.google.com/apikey> (compte Google, « Create API key », restreindre à l'API Gemini). La supprimer après la présentation.
- Sans clé : le site fonctionne en mode démonstration.

## 4. Données personnelles et risques (loi 09-08)
- **Niveau gratuit de Gemini** : Google peut utiliser les textes envoyés pour améliorer ses produits, et des relecteurs humains peuvent les lire (détachés du compte). Ses conditions disent de ne pas envoyer d'informations sensibles, confidentielles ou personnelles. Âge minimum : 18 ans ; service limité aux pays disponibles ; en Europe / Royaume-Uni / Suisse, seul le niveau **payant** est autorisé pour des utilisateurs finaux.
- **Mesures** : effacement des e-mails, téléphones et longs nombres avant l'envoi ; texte limité à 600 caractères ; aucune question n'est enregistrée ni journalisée par la plateforme (seule la dernière est affichée, pas conservée) ; avertissement affiché sous le champ de question.
- **Reste un risque** : un étudiant peut écrire dans son sujet un nom d'entreprise ou une information confidentielle, que l'effacement automatique ne reconnaît pas. **En démonstration, n'utiliser que des données fictives.**
- **Pour la vraie mise en ligne à l'école** : le niveau gratuit ne convient pas à de vrais sujets de stage. Il faut un compte **payant** (Google ne réutilise alors pas les données pour ses produits), ou un autre fournisseur, ou un modèle hébergé par l'école ; à décider avec le service informatique ([[08-Decisions-ouvertes]] #38). Les consignes données au modèle ne contiennent que l'aide du site, jamais de donnée de stage ou d'étudiant.
- **Plafonds** : 30 demandes par personne et par heure (évite d'épuiser le quota gratuit ; le quota exact est visible dans Google AI Studio, par projet, remis à zéro chaque jour).

## 5. Limites connues
- Les réponses de l'IA peuvent être fausses : l'assistant ne répond qu'à partir de l'aide, mais n'est pas infaillible.
- Le plafond par heure est compté dans la mémoire du serveur : il repart à zéro si le serveur redémarre (suffisant pour une démo ; à remplacer par un vrai cache partagé en ligne).
- Pas d'historique de conversation (volontaire : rien n'est conservé).
